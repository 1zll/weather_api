# 概要

## できること
- **7日間の詳細予報**: Open-Meteo APIから取得した最新の天気、最高/最低気温、最大風速、降水確率を表示します。
- **レスポンシブなテーブルUI**: PCでもスマホでも見やすい、左ヘッダー・右データ列のテーブルレイアウトを採用しています。
- **カレンダー色分け**: 日曜日を赤、土曜日を青に自動で色分けし、視認性を高めています。
- **ヘルプ機能**: 各項目の詳細をポップオーバー形式で確認できる機能（React Iconsを使用）を搭載しています。



## 特徴
- **デザインの一貫性**: Tailwind CSSのテーマ拡張機能を活用し、気温（赤/青）や曜日（赤/青）など、情報の意味に合わせたカラー設計を行っています。
- **変換レイヤーの実装**: APIから取得した数値の「天気コード」を、自作のロジックで適切なアイコン画像に変換して表示しています。
- **デプロイ最適化**: GitHub Pagesのサブディレクトリ構造に対応するためのパス解決を行い、公開環境でも画像やAPIが正しく動作するように調整しました。



## 作成理由
学校の授業でIllustratorを学ぶ中で、自分で制作したアイコンやデザインを、単なる画像作品として終わらせず、実際に動作するアプリケーションに組み込みたいと考えるようになりました。
そこから、APIを活用したアプリケーション開発に挑戦してみたいと考え、外部データを扱う実践的な制作テーマを検討しました。
その結果、APIとの連携が必須であり、日常的に利用シーンを想像しやすい1週間のお天気アプリを制作テーマとして選定しました。
また、近年主流となっているReact（フロントエンド）とNode.js（バックエンド）の構成を実践的に学ぶため、本制作ではこの技術構成を採用しました。
本制作を通して、UI構築、API連携、自作アイコンの実装を行い、デザインと開発の両面からアプリケーション制作を経験することを目的としています。

## 試行錯誤のプロセス（学びの記録）
開発中、特に技術的な壁にぶつかった3つのポイントと、その解決策です。

### 1. 404エラーとの戦い（環境によるAPI設計の違い）
当初、ローカル環境の構成を引き継ぎ `/api/weather` を叩いていましたが、GitHub Pages（静的ホスティング）にはバックエンドサーバーが存在しないため、404エラーが発生しました。


**【解決】** <br>
フロントエンドから直接外部APIを叩く設計に変更し、ブラウザ完結でデータを取得するように修正しました。


```javascript
// 修正前（失敗）：GitHub Pages上には自作サーバーが存在しないため404
const res = await fetch("/api/weather"); 

// 修正後（成功）：直接APIのフルURLを指定
const url = "[https://api.open-meteo.com/v1/forecast?latitude=35.6762&longitude=139.6503](https://api.open-meteo.com/v1/forecast?latitude=35.6762&longitude=139.6503)...";
const res = await fetch(url);
```


### 2. レイアウトの整合性（高さ固定によるズレの解消）
ヘッダー列（項目名）とデータ列（天気情報）を別々のコンポーネントで管理していたため、画面サイズによって高さが微妙にズレる問題に直面しました。


**【解決】** <br>
Tailwind CSSのテーマ拡張で定義した「共通の高さ」を両方に適用することで、ズレを解消しました。


```JavaScript
// tailwind.config.js で定義した md:h-row-date などを共通利用
<div className={`flex-col h-[70px] md:h-row-date py-2 md:py-4`}>
  {/* 内容の高さが揃うことを保証 */}
</div>
```


### 3. 公開環境における画像パスの解決
デプロイ後、天気アイコン画像が表示されない問題が発生しました。これはGitHub Pagesがサブディレクトリ構造を持つことが原因でした。


**【解決】** <br>
process.env.PUBLIC_URL を導入し、本番環境でも正しいパスが付与されるように修正しました。


```JavaScript
const publicUrl = process.env.PUBLIC_URL || "";
const getPath = (name) => `${publicUrl}/Icons/${name}`;

// アイコン取得時：どの環境でも画像が見つかるようにパスを生成
if ([0, 1].includes(code)) return { icon: getPath("Sunny.png") };
```


## 学んだ重要な気づき
- 静的ホスティングの特性: GitHub Pagesではサーバーサイド（Node.js等）は動かせないことを実体験しました。←本当にぽんこつすぎました、、💦
- 設計の優先順位: UIのズレは微調整より、設計段階で「ルール化（定数化）」する方が効率的であることを学びました。
